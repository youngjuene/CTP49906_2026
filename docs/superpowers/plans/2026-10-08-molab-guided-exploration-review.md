# Molab 탐구 활동 계획 1차 검토

검토일: 2026-10-08  
대상: [설계](../specs/2026-10-08-molab-guided-exploration-design.md), [구현 계획](2026-10-08-molab-guided-exploration.md)  
판정: 아래 보완을 두 문서에 반영했다. 구현을 시작할 수 있는 계획으로 구체화했으며 영상 채택·모델 결과·학생 사용성은 아직 확인 전이다.

## 후속 진행 기록

이 문서는 계획 검토 당시의 기록이다. 이후 사용자가 기존 소 영상과 같은 길이로 준비하도록 요청하여, 새 두 영상의 10초 소리 포함본/무음본과 기술 검증을 완료했다. 직접 청취·모델 검사·노트북 연결은 남아 있다. 최신 파일과 출처는 `avllm_interpretability/assets/LESSON_MEDIA_SOURCES.md`를 참고한다.

## 사용자 요구 반영

> 새 영상 추가까지 포함시켜서. 영어 비교는 없어도 된다. kr 노트북에서는 한글 프롬프트만 탐색하면 충분하다.

- 새 영상 2종을 첫 배포에 포함한다. 기존 영상과 합쳐 세 장면, 각 원본/무음 한 쌍을 제공한다.
- 한국어 질문은 소리·화면·둘을 함께 설명하는 세 예시와 직접 입력으로 구성한다.
- 영어 비교는 한국어판 수업·교사용 필수 절차·후속 배포 범위에서 제외한다. 기존 별도 영어판의 기능 회귀 검사는 유지한다.
- 저장 결과는 기본 설정의 18개 비교로 준비한다. GPU가 없는 학생도 영상·한국어 질문을 바꿔 탐색할 수 있어야 한다.

## 발견 사항과 반영

P1은 비교의 의미나 결과 연결이 틀어질 수 있는 문제, P2는 수업 운영·해석·기록에 영향을 주는 문제다. 아래는 검토 당시 계획의 문제이며, 구현에서 이미 발생했다고 단정하는 목록이 아니다.

| 우선순위 | 기존 계획의 문제 | 영향 | 반영한 수정 |
|---|---|---|---|
| P1 | 새 영상이 후속 범위이며 기존 두 파일명을 전제로 계획 | 새 영상 드롭다운만 추가해도 원본/무음 짝의 근거가 없음 | Task 1에 출처 확인·구간 선정·동일 영상/시간축·실제 무음 검증을 추가 |
| P1 | 실제 canonical의 experiment_config가 `02321` 쌍에만 키 발급 | 새 영상이 대조 쌍으로 연결되지 않거나 느슨한 파일명 추정으로 잘못 연결될 위험 | Task 3에서 검증된 카탈로그로 키 발급만 확장. matched_control_ids의 엄격한 조건 비교 유지 |
| P1 | 저장 결과를 scenario_id 하나로 조회 | 같은 활동의 다른 영상·질문 결과를 잘못 보여 줄 수 있음 | Task 2·6에 파일 해시·정확한 prompt·설정·모델을 포함한 plan_key와 별도 생성 출처 도입 |
| P1 | 한국어 질문 직접 탐색과 그에 따른 캐시/대조 조건이 없음 | 영상과 질문을 함께 바꾸고 한 효과로 오해하거나 과거 C를 재사용할 위험 | Task 2·3·5에 한국어 질문 3종·직접 입력·실행 조건 동결·캐시 무효화 검사 추가 |
| P2 | 저장 예제의 비교 ID를 학생 기록에서도 재사용 | 다시 열거나 다른 메모를 쓸 때 앞선 기록 덮어쓰기 가능 | Task 4에서 source_example_id와 새 comparison_id 분리, 보기와 기록 시작 구분 |
| P2 | 저장 결과는 두 활동 각각 하나뿐 | 새 영상·질문을 골라도 CPU 재생에서는 실제로 탐색하기 어려움 | Task 6에서 2활동×3영상×3질문=18개 실제 저장 비교 제공. 직접 입력·4프레임·부분 구간은 라이브 전용으로 명시 |
| P2 | 배열 정합성에 절대 오차 1e-6만 지정 | float32의 정상 반올림·합계 오차를 파일 손상으로 거부할 수 있음 | Task 6에서 dtype을 기록하고 토큰별·집계별 허용치를 분리, 정상 반올림과 실제 변조 검사 |
| P2 | 질문 변경·소리 제거·어텐션 연결 차단의 차이를 충분히 설명하지 않음 | 화면 질문이면 오디오가 안 들어간다고 생각하거나 차단을 완전한 정보 제거로 오해 | 설계 §2 및 Task 5·7에 실제 바뀌는 입력/연결을 명시. 다른 C 사이 Δ 순위 비교 금지 |

코드 대조 근거는 `avllm_interpretability/CTP49906_avllm_molab_kr.py`의 experiment_config, `src/run_ledger.py`의 matched_control_ids, `src/classroom_display.py`의 caption_cache_key, `src/teacher_forcing.py`의 teacher_forced_delta, `src/classroom_safety.py`의 디코딩/입력 상한이다. 기존 계산 함수의 측정 정의를 수정해야 하는 문제는 발견하지 못했다.

## 새 영상의 현재 상태

후보 설명 페이지에서 출처와 이용 조건을 확인했다. 실제 재생·청취·구간 선정·변환은 아직 하지 않았다.

- 동작과 소리 후보: [Tabla drums demo](https://commons.wikimedia.org/wiki/File:Tabla_drums_demo.webm), 제작자 tabladrumsonline, 파일 페이지의 CC BY 3.0 표기 확인. 손 동작과 타격음이 함께 보이고 들리는 구간이 있는지 확인 후 채택한다.
- 환경음 후보: [Rain in Rivne 1](https://commons.wikimedia.org/wiki/File:Rain_in_Rivne_1.webm), 제작자 Ата, 파일 페이지의 CC0 1.0 표기 확인. 실제 음질과 화면 밖 단서 여부를 확인하며, 맞지 않으면 다른 환경음 영상으로 교체한다.

후보 제목이나 라이선스 표기만으로 교육적 적합성과 시청각 정합성을 확인했다고 보지 않는다. 영상은 기대한 모델 답이나 큰 Δ를 얻기 위해 고르지 않는다. 새 파일은 노트북에서 외부 스트리밍 없이 사용하도록 저장소에 함께 둔다.

## 유지할 장점

- A의 입력 비교와 B의 동일 캡션 채점을 분리하는 기본 구조는 적절하다.
- 예상→관측→가능한 설명→다음 질문 흐름, 명시적 실행 버튼, 일부 실패 결과 보존은 유지한다.
- 고급 도구를 없애지 않고 첫 수업 뒤 선택 탐구로 배치한다.
- 실제 GPU 결과·출처를 보존하고 CPU 재생 경로로 같은 학습 화면을 제공한다.

## 실행 전후 확인 경계

현재 문서 검토에서 완료한 것은 범위·인터페이스·검사·단계별 완료 기준의 정리다. 다음 증거는 구현 단계에서 확보해야 한다.

1. 새 영상 두 개의 실제 시청·청취, 최종 구간·이용 조건, 원본/무음 시간축·시각 입력 일치.
2. 기본 8프레임·64토큰 설정의 메모리·문장 완결성, 18개 실제 결과와 저장 묶음 검증.
3. 최종 Molab에서 선택·실행·기록·다운로드의 동작 및 CPU 재생.
4. 비전공자 시범 활동에서 학생이 두 활동의 차이와 관찰의 한계를 설명할 수 있는지.

이 가운데 1~3이 끝나기 전에는 수업 배포 완료라고 보고하지 않는다. 4의 실제 수행 여부는 기술 검증과 별도로 보고한다. 이번 검토는 제품 코드 변경이나 GitHub 반영을 수행한 단계가 아니다.

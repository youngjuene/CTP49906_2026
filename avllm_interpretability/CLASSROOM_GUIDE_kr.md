# AVLLM 수업 진행 안내

목표는 **선택한 직접 어텐션 경로를 바꿨을 때, 정해진 입력과 캡션의 측정값이 어떻게 달라지는지** 설명하는 것입니다. 작은 Δ는 그 조건에서 측정된 효과가 작다는 뜻입니다. 간접 경로, 정보의 중복, 캡션 선택, 측정 민감도는 남아 있으므로 “모델은 소리를 전혀 듣지 않는다”로 결론 내리지 않습니다.

## 수업 전에

교사는 **검증한 노트북 파일과 그 파일이 지정하는 헬퍼 커밋**, 모델과 프로세서의 **같은 모델 리비전**, 패키지 버전을 한 조합으로 고정하고 기록합니다. 결과 묶음의 헬퍼 커밋·노트북 파일 SHA-256·패키지 버전을 확인합니다. 수정 버전의 짧은 원본·무음 쌍을 실제 사용할 GPU에서 다시 실행한 뒤 그 조합을 배포합니다. 준비된 코드가 있다는 것과 GPU에서 검증을 마쳤다는 것은 별도 상태입니다. 이전 QA의 RTX Pro 6000 실행 시간이나 RTX3090 소스 주석을 다른 학생 세션의 성능 보장으로 사용하지 않습니다.

학생은 로그인·Fork·GPU 연결 후 실제 실행 완료 표시를 확인합니다. 미리보기의 기존 그림과 자신의 실행을 구분합니다. 처음에는 기본 클립, 8프레임, 생성 상한 32토큰을 사용합니다. 가이드의 어텐션 그림 캡처 범위는 최대 2개 레이어로 유지합니다. 실험의 차단 레이어 범위와 그림을 저장하는 캡처 범위는 서로 다른 설정입니다.

## 활동 순서

1. **한국어 대조 쌍:** `영상에서 들리는 소리를 설명해 주세요`로 기본 클립을 실행하고, 나머지 설정을 유지한 채 제공된 무음 트랙 클립을 실행합니다. 실행 전에 가설을 씁니다. 이 두 실행의 ID를 명시적으로 짝짓습니다.
2. **영어 대조 쌍:** `Describe what you hear in the video`로 같은 원본·무음 쌍을 반복합니다. 쌍 안에서는 프롬프트·프레임·차단 경로·레이어·생성 상한을 모두 같게 유지합니다. 언어를 바꾸면 캡션 내용과 토큰화도 달라질 수 있습니다. 평균 Δ만으로 언어별 성능 우열을 결론 내리지 않습니다.
3. **한 변수 바꾸기:** 프레임 수 8→4 또는 차단 레이어 범위 중 하나를 선택해 새 대조 쌍을 만듭니다. 설정이 다른 이전 대조군을 새 실험에 붙이지 않습니다. 폼 값 변경 후 제출할 때 실행되며, 전역 코드 설정을 고치면 다른 셀도 다시 실행될 수 있습니다.
4. **경쟁 설명과 후속 실험:** 캡션 잘림, 간접 정보 경로, 서로 다른 생성 문장, 입력 언어 중 관측을 설명할 다른 이유를 적습니다. 그 설명을 구분하려면 어떤 한 변수를 다음에 바꿀지 제안합니다.

TF Δ는 고정한 캡션에 대한 `log p(차단) − log p(기준선)`입니다. 음수이면 해당 캡션의 확률이 낮아졌다는 뜻입니다. 실행 간 캡션이 다르면 길이로 나눈 평균값도 완전히 같은 질문을 비교하지 않습니다. 무음 트랙에는 오디오 토큰이 있으므로 무음에서 Δ=0이 항상 나와야 하는 것도 아닙니다. 생성 상한 때문에 문장이 끝나지 않았는지도 기록합니다.

## 입력과 세션 관리

프레임은 2~16의 짝수, 프롬프트는 공백만으로 구성하지 않고 4,000자 이하, 생성 상한은 8~128토큰입니다. 전처리 후 입력은 최대 4,096토큰입니다. 영상은 오디오 트랙을 포함해야 하며 최대 250 MiB·120초·1080p·60fps와 **누적 RGB 디코딩 512 MiB**를 모두 만족해야 합니다. 오디오는 모노 또는 스테레오, 48 kHz 이하이며 float32 PCM 디코딩 상한은 128 MiB입니다. 각 상한에 맞더라도 그 곱 때문에 거부될 수 있습니다. 메타데이터가 불명확한 영상은 짧고 낮은 해상도로 다시 인코딩합니다. 이 제한은 메모리 사용을 줄이는 방어선이며 모든 입력의 GPU 실행 성공을 보장하지 않습니다.

2026-09-14 확인한 [Molab 공식 안내](https://docs.marimo.io/guides/molab/#compute)는 세션 최대 12시간, 90분 초과 비활성 시 종료를 명시합니다. 정책은 바뀔 수 있으며 수업의 GPU 동시 할당이나 실행 시간을 보장하는 수치는 아닙니다. 수업일에 안내를 다시 확인합니다.

실행마다 결과 묶음과 워크시트를 내려받아 **실제로 파일을 열고** 실행 ID, 설정, 캡션, 토큰별 Δ, 판정·경쟁 설명이 있는지 확인합니다. 노트북 소스 저장만으로 실행 결과가 보존되지는 않습니다. Python이 만든 결과 파일과 폼 업로드는 세션 종료 뒤에도 남는다고 가정하지 않습니다. 파일 종류와 생성 시점에 따른 보존 규칙은 [공식 저장 정책](https://marimo.io/pages/molab/storage)을 확인합니다.

오류 뒤에는 오류문과 설정을 먼저 기록하고, 입력 크기를 줄여 다시 제출합니다. 메모리 부족이 반복되면 결과를 내보낸 뒤 커널을 재시작하고 기본 설정으로 돌아갑니다. 교사는 종료 후 재접속·결과 복구를 수업 전에 실제로 시험합니다. GPU를 사용할 수 없으면 replay와 미리 내보낸 그림으로 해석·대조 설계를 진행합니다. Replay는 저장된 안내 결과를 읽으며 새 파라미터 실험을 수행하지 않습니다.

개인 영상은 원격 런타임으로 전송되므로 수업에서는 먼저 제공된 샘플을 사용합니다. 얼굴·목소리·개인정보가 포함된 자료는 공유 범위를 확인한 뒤 사용합니다.

학생 기록지는 [한국어 워크시트](WORKSHEET_kr.md)를 사용합니다.

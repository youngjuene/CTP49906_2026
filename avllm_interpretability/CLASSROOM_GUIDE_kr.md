# AVLLM 수업 진행 안내

목표는 **선택한 직접 어텐션 경로를 바꿨을 때, 정해진 입력과 캡션의 측정값이 어떻게 달라지는지** 설명하는 것입니다. 작은 Δ는 그 조건에서 측정된 효과가 작다는 뜻입니다. 간접 경로, 정보의 중복, 캡션 선택, 측정 민감도는 남아 있으므로 “모델은 소리를 전혀 듣지 않는다”로 결론 내리지 않습니다.

## 수업에서 바꿀 것과 고정할 것

우선순위 번호는 처음 정한 **1·2·3·4·7·8**을 유지합니다. 먼저 🎯 티처 포싱으로 같은 답변의 확률 변화를 읽고, 마지막에 🎛️ 다양성 프로브로 측정 대상을 넓힙니다.

| 우선순위 | 학생이 바꿀 설정 | 활동의 질문 |
|---|---|---|
| **1 · 직접 경로** | `answer→audio` / `answer→video` | 같은 캡션이 어느 직접 연결의 차단에 더 민감한가? |
| **2 · 대조 조건** | 제공 원본 / 제공 무음 트랙 | 무음에서도 효과가 나타나는가? 기대와 다르면 해석을 어떻게 바꿀까? |
| **3 · 질문 초점** | 소리 / 보이는 내용 / 둘 다 / 직접 작성 | 같은 언어에서 질문의 과제가 바뀌면 관측도 달라지는가? |
| **4 · 레이어 대역** | 전체 `[0,36)` / 초반 `[0,12)` / 중반 `[12,24)` / 후반 `[24,36)` | 같은 캡션의 점수가 어느 대역 차단에 더 민감한가? |
| **7 · 새 클립** | 업로드한 교사 준비 영상 또는 사용 가능한 학생 영상 | 새 장면에서도 관측이 유지되는가? 어떤 대조 영상이 더 필요한가? |
| **8 · 고급 경로** | `query_text`, 교차 모달 source/target, 여러 규칙 | 다른 직접 경로 또는 복합 차단을 어떻게 대조할까? |

**프레임 수(기존 우선순위 5)는 원래 기준인 8로 고정**하며 학생 폼에서 바꾸지 않습니다. 언어 비교(6)는 프롬프트 셀의 선택적 주석 안내로만 남깁니다. 정규 활동이나 제출 표에 별도 영어 쌍을 요구하지 않습니다.

처음에는 source `answer`, 한국어 소리 질문, 전체 레이어, 생성 상한 32토큰을 사용합니다. 생성 상한은 학습용 독립 변수가 아니라 **캡션 잘림을 복구하는 운영 설정**입니다. 문장이 잘리면 상한을 늘리고 비교할 실행을 모두 같은 상한으로 다시 만듭니다. 표시 임계값은 하이라이트만 바꿉니다. 가이드 어텐션 그림의 캡처 범위는 최대 2개 레이어이며, 실험에서 차단하는 레이어 대역과 다른 설정입니다.

실제 GPU 검사에서 보이는 내용 질문은 32토큰과 128토큰 모두 상한에 도달했고, 마지막 글자가 `�`로 끝났습니다. 상한을 늘려도 완성·정확성은 보장되지 않습니다. 잘린 끝부분을 의미 있는 단어로 해석하지 말고, 캡션·상한·잘림 표시를 함께 남기세요. 반복·다른 언어 조각·무음 영상의 소리 환각도 관측 대상으로 다룹니다.

## 활동 순서

### 첫 활동 — 우선순위 1·2, 네 실행

프롬프트를 `영상에서 들리는 소리를 설명해 주세요`, 프레임을 8, 레이어를 전체, 생성 상한을 32로 유지합니다. 각 실행 **전에** 가설을 씁니다.

| 순서 | 클립 | 직접 경로 |
|---|---|---|
| A1 | 원본 | `answer→audio` |
| A2 | 원본 | `answer→video` |
| B1 | 제공 무음 | `answer→audio` |
| B2 | 제공 무음 | `answer→video` |

먼저 A1↔A2와 B1↔B2에서 **같은 클립의 같은 캡션**을 비교합니다. 같은 클립 내용·프롬프트·프레임·생성 상한·모델에서 target이나 레이어만 바꾸면 기준 캡션을 재사용합니다. 캡션 텍스트와 토큰 수가 같은지도 기록으로 확인하세요.

그다음 A1↔B1, A2↔B2에서 원본/무음 조건을 비교합니다. 자동 대조 연결은 target·레이어 등 기록된 설정이 같은 제공 원본/무음 쌍에만 붙습니다. **클립을 바꾸면 캡션도 새로 생성되므로 두 조건이 동일한 문장을 채점했다고 가정하지 않습니다.**

### 후속 활동 — 우선순위 3·4·7·8

각 활동은 앞서 쓴 가설을 구분하는 한 비교를 설계합니다. 모든 설정의 조합을 전부 실행하는 과제가 아닙니다.

- **3 · 질문 초점:** 클립·target·대역·상한을 고정하고 소리 질문을 `영상에서 보이는 내용을 설명해 주세요`로 바꾸어 한 번 비교합니다. 시간이 남으면 `영상에서 보이는 것과 들리는 소리를 설명해 주세요` 또는 직접 쓴 한국어 질문으로 확장합니다. 무음과의 주장을 하려면 해당 질문의 새 무음 실행도 만듭니다. 질문 변경은 캡션 재생성을 동반합니다.
- **4 · 레이어 대역:** 클립·질문·target을 고정하고 전체에서 초반·중반·후반 중 한 대역으로 바꿉니다. 대역끼리는 각각 12개 레이어입니다. 전체 대역은 더 많은 엣지를 차단하므로 대역 효과의 합이나 크기만으로 융합 위치를 단정하지 않습니다. 원본/무음 비교에도 같은 대역을 사용합니다.
- **7 · 새 클립:** 먼저 짧은 교사 준비 클립을 업로드하고 audio/video target을 비교합니다. 장면이 바뀌어도 이전 주장이 유지되는지 확인합니다. 업로드는 기존 무음 샘플과 자동으로 짝지어지지 않습니다. 자신의 대조 영상을 사용하면 무엇을 같게 만들었는지와 두 실행 ID를 워크시트에 직접 남깁니다.
- **8 · 고급 경로:** 먼저 🎯에서 `answer→query_text`를 시험합니다. 이후 🎛️ 다양성 프로브에서 `audio→video`, `audio→query_text`를 각각 실행한 뒤, 고급 필드의 `audio,video,0,36 ; audio,query_text,0,36`으로 둘을 함께 차단합니다. Compare를 켜서 기준선과 비교합니다. 측정값은 캡션 확률에서 **오디오 위치의 top-1 문자열 다양성**으로 바뀝니다. 복합 효과가 단일 효과의 합이라고 가정하지 않습니다. `query_text`는 질문 외 채팅 구조·특수 토큰도 포함합니다.

TF Δ는 고정한 캡션에 대한 `log p(차단) − log p(기준선)`입니다. 음수이면 해당 캡션의 확률이 낮아졌다는 뜻입니다. 실행 간 캡션이 다르면 토큰당 평균값도 완전히 같은 질문을 비교하지 않습니다. 첫 캡션 토큰은 마지막 프롬프트 위치에서 예측되므로 answer-only 직접 차단 범위 밖입니다. 무음 트랙에도 오디오 토큰이 있으므로 Δ=0을 보장하지 않습니다.

마지막에는 [워크시트](WORKSHEET_kr.md)에 **바꾼 것·고정한 것·관측값·경쟁 설명·결과가 말해 주지 않는 것**을 기록합니다. 큰 효과를 얻는 것보다 해석 가능한 대조를 만드는 것이 중요합니다.

## 입력과 세션 관리

수업 UI는 8프레임을 유지합니다. 프롬프트는 공백만으로 구성하지 않고 4,000자 이하, 생성 상한의 운영 범위는 8~128토큰입니다. 전처리 후 입력은 최대 4,096토큰입니다. 영상은 오디오 트랙을 포함해야 하며 최대 250 MiB·120초·1080p·60fps와 **누적 RGB 디코딩 512 MiB**를 모두 만족해야 합니다. 오디오는 모노 또는 스테레오, 48 kHz 이하이며 float32 PCM 디코딩 상한은 128 MiB입니다. 각 상한에 맞더라도 그 곱 때문에 거부될 수 있습니다. 메타데이터가 불명확한 영상은 짧고 낮은 해상도로 다시 인코딩합니다. 이 제한은 메모리 사용을 줄이는 방어선이며 모든 입력의 GPU 실행 성공을 보장하지 않습니다.

2026-09-14 확인한 [Molab 공식 안내](https://docs.marimo.io/guides/molab/#compute)는 세션 최대 12시간, 90분 초과 비활성 시 종료를 명시합니다. 정책은 바뀔 수 있으며 수업의 GPU 동시 할당이나 실행 시간을 보장하는 수치는 아닙니다. 수업일에 안내를 다시 확인합니다.

실행마다 결과 묶음과 워크시트를 내려받아 **실제로 파일을 열고** 실행 ID, 설정, 캡션, 토큰별 Δ, 판정·경쟁 설명이 있는지 확인합니다. 노트북 소스 저장만으로 실행 결과가 보존되지는 않습니다. Python이 만든 결과 파일과 폼 업로드는 세션 종료 뒤에도 남는다고 가정하지 않습니다. 파일 종류와 생성 시점에 따른 보존 규칙은 [공식 저장 정책](https://marimo.io/pages/molab/storage)을 확인합니다.

다운로드가 도착하지 않으면 하단의 **JSON 보기 / Markdown 보기**를 펼칩니다. 작은 기록은 전체 내용을 각각 UTF-8 `lab_evidence.json`·`lab_log.md`로 저장합니다. 큰 기록은 화면 출력 제한을 피하도록 조각으로 나뉘므로 다음 순서로 복원합니다.

1. 조각을 하나씩 열고 표시된 **JSON 전체**를 같은 폴더에 `lab_evidence.json.part001.json`, `lab_evidence.json.part002.json` …으로 저장합니다. Markdown 보기의 조각도 JSON 형식이며 `lab_log.md.part001.json`, `lab_log.md.part002.json` …으로 저장합니다. 조각 안의 `text`만 꺼내거나 내용을 수정하지 않습니다.
2. 각 보기의 **“복사한 조각을 원본 파일로 복원하는 Python 코드”**를 같은 폴더에서 실행합니다. 학생에게 Python 실행이 어렵다면 교사가 돕습니다. 코드는 순서·누락·SHA-256을 확인하고 원본 `lab_evidence.json` 또는 `lab_log.md`를 만듭니다. 검사 오류가 나면 해당 조각을 다시 복사하며 검사를 생략하지 않습니다.
3. 복원된 두 파일을 다시 열어 실행 ID·기록 수·전체 캡션을 확인하고 워크시트와 함께 제출합니다. 조각 수는 결과 크기에 따라 달라집니다.

이번 12건의 결과는 JSON 25조각에서 2,452,521바이트, Markdown 23조각에서 2,226,147바이트로 복원했고 두 파일의 SHA-256 일치를 확인했습니다. 이는 복사·복원 경로의 검증이며 직접 다운로드 수신 여부는 미확인입니다. 수업에서는 전체 파일 다운로드를 먼저 사용합니다.

오류 뒤에는 오류문과 설정을 먼저 기록하고, 입력 크기를 줄여 다시 제출합니다. 메모리 부족이 반복되면 결과를 내보낸 뒤 커널을 재시작하고 기본 설정으로 돌아갑니다. 교사는 종료 후 재접속·결과 복구를 수업 전에 실제로 시험합니다. GPU를 사용할 수 없으면 replay와 미리 내보낸 그림으로 해석·대조 설계를 진행합니다. Replay는 저장된 안내 결과를 읽으며 새 파라미터 실험을 수행하지 않습니다.

입력 거부 뒤에도 직전의 성공 결과가 화면에 남을 수 있습니다. 오류문을 확인하고 결과에 표시된 클립·질문·규칙·실행 ID가 방금 제출한 설정과 일치하는지 확인하세요. 거부된 입력은 새 실행 기록을 만들지 않습니다.

개인 영상은 원격 런타임으로 전송되므로 수업에서는 먼저 제공된 샘플을 사용합니다. 얼굴·목소리·개인정보가 포함된 자료는 공유 범위를 확인한 뒤 사용합니다.

학생 기록지는 [한국어 워크시트](WORKSHEET_kr.md)를 사용합니다.

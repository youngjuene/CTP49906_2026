### 한국어판 노트북

한국어판은 설명·폼·그래프·기록표와 기본 프롬프트에 한국어를 사용합니다. 정규 활동에서는
**같은 언어의 질문 초점**을 바꿉니다. 프롬프트 셀의 접힌 직접 작성 영역에 다른 언어를
시도할 수 있다는 선택적 주석을 두며, 별도 영어 대조 쌍은 제출 필수가 아닙니다.
언어를 바꾸면 질문의 토큰화와 생성 캡션도 달라질 수 있으므로 평균 Δ만으로 언어별
성능 우열을 판단하지 않습니다.

**작은 Δ의 해석:** 비슷한 캡션이나 0에 가까운 Δ는 이 모델·클립·프롬프트·레이어 설정에서
선택한 직접 연결에 대한 측정된 민감도가 작았다는 결과입니다. 소리를 전혀 사용하지
않았거나 오디오 경로가 없다는 증거는 아닙니다. 간접 전달, 정보의 중복, 캡션 선택과 지표의
민감도도 가능한 설명입니다. 무음에도 오디오 토큰과 표현이 있으므로 Δ=0을 보장하지 않습니다.
관측값과 생성 캡션을 직접 기록하고, 서로 다른 캡션의 비교라는 한계도 남기세요.

GPU 없는 재생용 산물은 프롬프트가 다르므로 따로 있습니다
([`precomputed_kr/`](precomputed_kr/)). 영어판 팩을 가리키면 `meta.json` 검증이
프롬프트 불일치를 감지해 재생을 거부합니다.

영어로 남겨 둔 것은 두 가지입니다. (1) 실습 기록의 `kind`·`metric` 값
(`band_sweep`, `caption_similarity` 등) — 이 값들은 `lab_log.jsonl`과 워크시트
내보내기에도 그대로 들어가므로, 표의 한 줄을 파일에서 찾으려면 같은 문자열이어야
합니다. (2) 프로브 그리드 위젯 **안쪽** 라벨(`undecodable`, `not a word` 등) — 그
위젯은 `src/`에 있고 두 노트북이 공유하는 코드라서, 여기서 번역하면 영어판까지
함께 바뀝니다.

### 왜 필요한가

*"어떤 사람이 피아노를 치고 있다"* 같은 캡션은, 모델이 영상을 봤든, 소리를 들었든, 아니면
그냥 언어적 사전 지식(language prior)에 기댔든 똑같이 그럴듯해 보입니다. 이 노트북은 그런
경우들에 대한 가설을 세우고 시험할 두 가지 해석 가능성(interpretability) 프로브를
학생들에게 제공합니다.

- **Logit Lens** — 각 레이어의 **정규화 전 잔차 스트림(raw residual stream)**을 오디오
  토큰 위치에서 꺼내 `lm_head`를 바로 적용합니다. thinker의 최종 RMSNorm을 거치지 않으며,
  오디오 위치에는 보정된 다음-토큰 언어 모델 목적도 없습니다. 따라서 디코딩된 토큰은
  실제 중간 다음-토큰 예측이 아니라 진단용 프로브입니다.
- **Attention Knockout** — 선택한 레이어에서 source→target의 **직접 어텐션 엣지**만
  막고 다시 실행합니다. 모달리티 자체나 잔차 스트림의 정보를 제거하지 않으며, 간접 경로도
  남습니다. 따라서 결론은 이 특정 엣지 개입에 한정해야 합니다.

목표는 어떤 수치를 재현하는 것이 아니라, *모델을 내부에서 읽어 내는* 감각을 기르고
"X를 막으면 출력이 Y처럼 바뀔 것이다"라는 **반증 가능한(falsifiable)** 가설을 세우는
연습을 하는 것입니다.

### 실행 방법 (molab)

1. 로그인한 molab에서 **`+ New notebook → Mirror from GitHub`**를 선택하고 교사가
   배포한 한국어 노트북 URL을 붙여 넣습니다. 읽기 전용 미리보기라면 **Fork notebook**으로
   자신의 사본을 만듭니다.
2. 위쪽 **Configure compute**에서 GPU를 선택한 뒤 **Save and restart**를 누릅니다.
   CPU만 보이면 GPU 배정을 확인하세요. 기기의 총 VRAM뿐 아니라 남은 VRAM·호스트 RAM·
   다운로드 공간과 입력 크기도 실행 가능성에 영향을 줍니다.
3. **Run all**을 누르고 설치·모델 로드·시범 실행이 끝날 때까지 기다립니다. 첫 실행에는
   모델 다운로드가 포함되고, 이후 실행은 로드된 모델을 재사용합니다. 표시된 패키지 버전과
   각 섹션의 실제 완료/생략/실패 상태를 확인하고, 실행 중에는 제출을 반복하지 마세요.
4. 🎯 티처 포싱 폼에서 **원본/무음 × audio/video의 네 실행**부터 시작합니다. 질문은
   **소리 설명**, 레이어는 **전체**, 프레임은 고정8, 생성 상한은32입니다.
   [워크시트](WORKSHEET_kr.md)에 실행 전 가설과 실행 뒤 ID·캡션·Δ를 기록합니다.

교사는 **검증한 노트북 파일과 그 파일이 지정하는 헬퍼 커밋**을 한 쌍으로 배포하세요.
현재 기본 `REPO_REF`는 `1df22a98697db72e4c2a5725156951fcbf9348b7`이며, 모델과
프로세서의 `MODEL_REVISION`은 `f75b40e3da2003cdd6e1829b1f420ca70797c34e`입니다.
환경 변수 `CTP49906_REPO_REF`로 헬퍼를 바꾸면 그 조합을 다시 검증해야 합니다. 결과에는
헬퍼 커밋·노트북 파일 SHA-256·실제 패키지 버전이 기록됩니다. 셋업은 지정한 저장소 버전을
준비하며, 그 클론에 수정된 추적 파일이 있으면 덮어쓰지 않고 중단합니다.

호환되는 PyTorch/CUDA를 준비한 로컬 머신에서는 이 디렉터리에서
`uvx marimo edit CTP49906_avllm_molab_kr.py`로 열 수 있습니다. 배포할 GPU와 런타임에서
원본/무음 쌍을 미리 실행해 확인하세요. 이전 QA의 메모리·시간 수치는 다른 세션의 보장이 아닙니다.

**GPU가 없다면? GPU 없는 재생.** molab의 GPU를 쓸 수 없을 때는 상단 설정 셀에서
`USE_PRECOMPUTED = True`로 바꾸세요. 한국어판은 [`precomputed_kr/`](precomputed_kr/)의
캡션·프로브·축약 어텐션 결과를 읽으며 모델 가중치를 내려받거나 GPU 추론을 하지 않습니다.
의존성 설치와 저장소 접근은 여전히 필요합니다. 기본값은 `False`(라이브 모델)입니다.
레이어 대역의 새 생성, 두 플레이그라운드, 티처 포싱은 replay에서 생략됩니다. 저장된
결과를 읽고 대조 실험을 설계하는 대안이며 새 파라미터 실험을 수행하는 기능은 아닙니다.
영어판 [`precomputed/`](precomputed/)와 바꾸어 쓰지 마세요. 한국어 산물을 다시 만들 때는
[`precomputed_kr/README.md`](precomputed_kr/README.md)의 한국어 프롬프트·출력 경로를 사용합니다.

### 녹아웃 규칙 읽는 법

모든 녹아웃은 튜플 **`(source, target, start_layer, end_layer)`**이며, 의미는 다음과
같습니다.

> *thinker 레이어 `[start_layer, end_layer)` 구간에서, `source` 타입 토큰이 `target`
> 타입 토큰에 어텐션하는 것을 금지한다.*

학생들이 자주 헷갈리는 두 가지를 먼저 짚고 갑니다.

- **방향성이 있습니다.** 어텐션은 source(보는 쪽 토큰)에서 target(읽히는 쪽 토큰)으로
  흐릅니다. `generated → video`(생성 쿼리에서 비디오 키로 향하는 직접 연결 차단)와 `video → generated`는 완전히
  다른 개입입니다. 의미 있는 방향은 거의 항상 *뒤쪽 토큰이 앞쪽 토큰을 읽는* 것인데,
  모델이 인과 마스킹(causal masking)되어 있어 한 토큰은 자기 자신과 그 이전의 모든
  것에만 어텐션할 수 있기 때문입니다.
- **`end_layer`는 배타적(exclusive)입니다.** `[0, 36)`은 레이어 0부터 35까지, 즉 3B
  thinker에서는 전부를 의미합니다(노트북이 실제 레이어 수를 출력합니다). 창을 좁히면
  **레이어 대역 민감도**를 시험할 수 있지만, 그것만으로 융합 모듈의 위치가 특정되지는
  않습니다. 정보가 이미 간접 경로로 이동했거나 막히지 않은 엣지로 우회할 수 있습니다.

개입에 쓰는 여섯 가지 위치 토큰 타입(모두가 모달리티인 것은 아님):

| 타입 | 무엇인가 |
| --- | --- |
| `query_text` | 질문 문장뿐 아니라 채팅 구분자·특수 토큰 등 프롬프트 구조도 포함하는 묶음. |
| `audio` | 영상의 **사운드트랙**에서 나온 토큰. |
| `video` | 샘플링된 **프레임**에서 나온 토큰. |
| `image` | 정지 이미지 토큰 — 영상 입력에는 없으므로 여기선 작동하지 않음. |
| `generated` | 자기회귀 디코딩 중에 모델이 **생성하는** 토큰(생성하는 동안에만 존재). |
| `answer` | 모델 자신의 캡션을 **티처 포싱으로 다시 입력**한 것 — 순전파 한 번으로 점수를 매길 수 있게. 티처 포싱 Δ log-lik 섹션이 사용하며, 토큰 id가 아니라 위치로 태그됨. |

### 고급 참고: 녹아웃 쌍(pair) 카탈로그

활동 8 이후 찾아볼 참고입니다. 첫 활동은 아래 카탈로그 대신 🎯의 `answer→audio/video`를 사용합니다. 처음 세 개는 `source`가 `generated`이므로 **Attention
Knockout 셀**에 속하고(생성 중에 작동), 마지막 두 개는 **오디오 위치 logit lens**를 바꾸므로
**플레이그라운드**에 속합니다.

| 규칙 | 던지는 질문 | 출력 변화가 의미하는 것 |
| --- | --- | --- |
| `generated → video` | *이 레이어 대역에서 생성 토큰 쿼리가 비디오 키를 직접 읽지 못하면 무엇이 바뀌는가?* | 변화는 해당 엣지에 대한 민감도와 일치합니다. 시각적 근거를 주장하려면 대조군이 필요하며, 무변화는 중복·간접 전달 때문일 수도 있습니다. |
| `generated → audio` | *생성 토큰 쿼리가 오디오 키를 직접 읽지 못하면 무엇이 바뀌는가?* | 변화만으로 “진짜 듣기”가 입증되지는 않습니다. 무음/불일치 대조군과 우회 경로를 시험하세요. |
| `generated → query_text` | *생성 토큰이 지시문을 직접 다시 읽지 못하면 무엇이 바뀌는가?* | 이 엣지 의존성과 일치하는 변화인지 확인하되, 지시 정보가 이미 다른 곳에 인코딩됐을 가능성도 비교하세요. |
| `audio → video` | *오디오 위치 프로브 통계가 비디오 키로 향하는 직접 엣지에 민감한가?* | 다양성 변화는 설명해야 할 효과일 뿐, 시각→오디오 융합이나 의미 품질을 입증하지 않습니다. |
| `video → audio` | *비디오 토큰 쿼리가 오디오 키로 향하는 직접 엣지에 민감한가?* | 후속 변화는 교차 모달 가설을 제안하지만, 마스킹·재정규화 효과와 구분할 대조군이 필요합니다. |

> **왜 다양성 스코어보드에서는 `generated`가 아무 일도 하지 않는가.** 다양성 스코어보드는
> 프롬프트에 대한 순전파(forward pass) 1회만 돌리므로(자기회귀 디코딩 없음), 규칙이 작용할
> **`generated` 토큰이 없습니다.** 거기서 `generated → …` 규칙은 아무것도 막지 못하고 Δ가
> 바뀌지 않는 설정입니다. 한국어판 폼은 이 선택을 제외하고, 유효하지 않은 고급 규칙은 검증합니다. **source**를
> 실제로 존재하는 토큰 종류(`audio`, `video`, `query_text`)로 두세요.
>
> **답변이 source가 *될 수 있는* 곳: 티처 포싱.** *"답변 쿼리가 오디오 키를 직접 읽지
> 못하면 같은 캡션의 확률이 달라지는가?"*를 측정하려면 캡션을 입력으로 고정해야 합니다.
> **티처 포싱 Δ log-우도** 섹션이 바로 그 일을 합니다: 캡션을 한 번 생성하고, **`answer`**로
> 태그해 다시 입력한 뒤, `answer → audio`(또는 `→ video`, `→ query_text`)를 연속적이고
> 결정론적인 **Δ log-lik = knockout − baseline**으로 점수화합니다 — 음수는 경로가 잘리자
> 모델이 자기 캡션에 더 낮은 확률을 할당했다는 뜻입니다. 이는 통제된 직접-엣지 개입
> 측정이지만 target 모달리티가 캡션 의미를 제공했다는 증명은 아닙니다. 여기서는 답변이
> 입력으로 존재하기 때문에 `answer` source가 의미를 갖습니다.

첫 캡션 토큰은 **마지막 프롬프트 위치**에서 예측되므로 answer-only 규칙의 직접 차단 범위
밖에 있습니다. 텍스트 띠는 UTF-8가 완성될 때까지의 토큰 점수를 표시 그룹에 합산하며,
특수 토큰은 `⟨special⟩` 단위로 분리합니다. 이는 글자별 확률 배분이 아닙니다. 임계값 아래
선택된 표시 단위의 비율은 **전체 음의 감소량 중 차지하는 몫**이며, 양·음수가 상쇄된
순합계 Δ의 기여율이 아닙니다. 비교 색 범위는 ±8 nats이고, 수치는 툴팁과 표에서 확인합니다.

### 활동 폼 (직접 만지는 단계)

🎯 티처 포싱을 먼저, 🎛️ 다양성 프로브를 나중에 진행합니다. 두 폼 모두 **▶로 제출할 때**
새 실험을 실행합니다. 전역 코드의 설정을 고치면 다른 셀도 다시 실행될 수 있으므로
학생 탐색은 폼에서 하세요. 입력·활성값·어텐션·캐시는 추가 RAM/VRAM을 사용합니다.

| 우선순위 | 셀·위젯 | 학생이 바꿀 것 |
|---|---|---|
| **1** | 🎯 target | `audio` / `video`: 답변의 직접 연결 비교. source는 `answer`. |
| **2** | 🎯 클립 | 제공 원본 / 제공 무음 트랙. 같은 target·대역·질문·상한으로 대조. |
| **3** | 프롬프트 프리셋 | **소리 설명 / 보이는 내용 설명 / 시청각 함께 설명 / 직접 작성**. |
| **4** | 🎯 레이어 프리셋 | **전체 / 초반 / 중반 / 후반**: 36레이어 기준 `[0,36)` / `[0,12)` / `[12,24)` / `[24,36)`. |
| **7** | 접힌 **활동 7 · 새 클립 업로드** 영역 | 업로드 조건을 선택하고 파일 제공. 기존 무음 샘플과 자동으로 연결되지 않음. |
| **8** | 🎛️ 고급 규칙 | `query_text`, 교차 모달 source/target, 복합 규칙과 기준선 비교. |

- **프레임(5):** 두 폼 모두 원래 기준 **8로 고정**하며 조절 위젯을 두지 않습니다.
- **언어(6):** 프롬프트의 직접 작성 영역에 있는 선택적 주석입니다. **직접 작성**을 선택해야
  그 입력이 적용됩니다. 필수 활동은 같은 언어의 질문 과제를 비교합니다.
- **프롬프트:** 공백만 있는 질문은 거부하며 최대4,000자입니다. 프리셋을 선택했을 때는
  접힌 직접 작성 입력 대신 해당 프리셋의 질문이 적용됩니다.
- **캡션 잘림 복구(🎯):** 접힌 운영 설정의 기본 상한은32, 허용 범위는8~128입니다.
  문장이 잘렸다면 상한을 늘리고 관련 비교 실행을 모두 같은 상한으로 다시 만듭니다.
  학습용 비교 변수로 토큰 상한을 탐색하는 활동은 두지 않습니다.
- **고급 규칙(🎛️):** `source,target,start,end`를 `;`로 구분합니다. 예를 들어
  `audio,video,0,36 ; audio,query_text,0,36`은 두 직접 경로를 함께 차단합니다.
  고급 입력이 채워져 있으면 단일 규칙보다 우선합니다. **Compare**를 켜면 기준선과의
  다양성 Δ를 읽을 수 있습니다. 단일 규칙 둘과 복합 규칙을 각각 실행해 비교하세요.

캡션 캐시는 클립 내용·질문·8프레임·생성 상한·모델 식별 정보가 같을 때 재사용합니다.
같은 조건에서 target이나 레이어만 바꾸면 같은 캡션을 채점하지만, **클립이나 질문 변경은
새 캡션 생성**을 동반합니다. 비교 전에 전체 캡션과 실제 토큰 수가 같은지 확인하세요.

영상 제한은 **250 MiB·120초·1920×1080(세로1080×1920)·60fps 이하**이며, 누적 RGB
디코딩512 MiB 한도도 함께 만족해야 합니다. 오디오 트랙은 모노/스테레오·48kHz 이하이며
float32 PCM 디코딩128 MiB 한도를 적용합니다. 불명확한 메타데이터나 오디오 트랙이 없는
영상은 거부합니다. 무음 대조군도 실제 무음 트랙을 포함해야 합니다. 입력은 전처리 후
최대4,096토큰이며 🎯는 생성 상한만큼의 토큰 자리를 추가로 확보합니다. 어텐션 **그림 캡처**는
최대2개 레이어입니다. 이는 녹아웃 레이어 범위를2개로 제한한다는 뜻이 아닙니다.
각 한도에 맞아도 GPU 실행 성공이 보장되지는 않습니다. 상세한 복구·세션 안내는
[수업 진행 안내](CLASSROOM_GUIDE_kr.md)를 보세요.

스코어보드 읽는 법: 각 레이어는 **오디오 위치에서 디코딩한 서로 다른 top-1 문자열
수**로 점수가 매겨집니다. **음(−)의 Δ**는 녹아웃 뒤 서로 다른 프로브 문자열 수가 줄었다는
뜻일 뿐, 표현의 개선·악화나 모달리티 융합을 입증하지 않습니다. 평평한 Δ도 무민감성,
중복/간접 경로, 거친 측정치, 또는 (`generated` source처럼) 작동할 수 없는 개입 중 무엇인지
추가 대조군으로 구분해야 합니다.

### 학생 활동 순서

[한국어 워크시트](WORKSHEET_kr.md)에 ▶ **전에** 가설을 쓰고, 실행 뒤에 ID·설정·전체 캡션·
총 Δ·평균 Δ·잘림 여부·경쟁 설명을 기록합니다. 프레임은 전 활동에서8로 유지합니다.
모든 조합을 전부 실행하는 대신 각 활동에서 가설을 구분할 한 비교를 고릅니다.

| 순서 | 활동 | 비교에서 확인할 것 |
|---|---|---|
| **1·2** | 🎯에서 **소리 설명**, 전체 레이어, 상한32로 원본→audio, 원본→video, 무음→audio, 무음→video 실행. | 같은 클립 안의 target 비교는 같은 캡션인지 확인. 원본/무음의 같은 target끼리 연결하되, 두 클립의 캡션 차이를 기록. |
| **3** | 클립·target·대역을 고정하고 **보이는 내용 설명**, 이어 **시청각 함께 설명** 또는 직접 쓴 한국어 질문으로 변경. | 질문을 바꾸면 캡션도 다시 생성됨. 원본/무음 주장을 하려면 새 질문의 대조 실행도 생성. |
| **4** | 같은 클립·질문·target에서 전체→초반/중반/후반 중 한 대역으로 변경. | 같은 캡션에 대한 대역 민감도. 12레이어 대역과 36레이어 전체의 개입 크기 차이 및 간접 경로를 고려. |
| **7** | 접힌 업로드 영역으로 새 클립을 넣고 audio/video target을 비교. | 새 장면에서도 주장이 유지되는가? 업로드한 대조 영상의 조건과 대응 ID는 직접 기록. |
| **8** | `query_text` 경로, 🎛️에서 `audio→video`와 `audio→query_text`의 단일·복합 차단 비교. | TF Δ와 문자열 다양성을 구별. 복합 효과가 단일 효과의 합이라는 가정을 검토. |

자유 생성 대역 비교는 활동 4·8 뒤의 선택 보충입니다. 새로 생성된 답변끼리의 문자열 변화와
같은 캡션을 고정해 채점한 TF Δ는 다른 질문을 측정합니다. `query_text`에는 채팅 구조와
특수 토큰도 포함됩니다. 다양성 변화는 의미 품질·융합·모델의 생각을 입증하지 않습니다.

노트북 하단에서 **`lab_log.md`와 `lab_evidence.json`을 함께 내려받고 실제로 열어**
실행 ID·설정·캡션·토큰별 Δ·판정이 있는지 확인하세요. 동일한 설정·결과는 한 행으로
합쳐지며 기존 판정이 보존됩니다. 제공된 원본/무음 클립은 기록된 설정이 맞을 때만
연결되지만, 연결 표시가 유효한 인과 결론을 보증하지는 않습니다. 오류나 세션 종료에
대비해 결과를 내보내고, 메모리 부족 뒤에는 오류·설정을 기록한 다음 커널 재시작과 작은
입력으로 복구하세요. Replay 결과는 자신의 새 실행과 구분해 제출합니다.
다운로드 파일을 받지 못하면 노트북의 **“JSON 보기 · 다운로드가 안 되면 복사”**와 Markdown
보기를 펼칩니다. 작은 기록은 전체 내용을 UTF-8 `lab_evidence.json`·`lab_log.md`로 저장합니다.
큰 기록은 조각별 JSON 전체를 같은 폴더에 `lab_evidence.json.part001.json`,

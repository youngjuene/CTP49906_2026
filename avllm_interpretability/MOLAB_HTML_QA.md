# 개인 Molab HTML 실행판: 구조와 GPU 검증 기준

## 세 장면 드롭다운 연결 — 2026-10-09

- 10초 영상 세 장면의 원본·무음을 미리보기와 다양성·티처 포싱 폼에 연결했다. 두 실험에는 기존 업로드도 남겨 두었다. 가이드·경로 차단 시범은 장면 1을 사용한다.
- 미리보기만 바꾸면 선택한 파일을 표시하며 계산 셀은 실행하지 않는다. 실험 폼은 제출 전까지 초안이고, 제출한 선택값이 실제 영상 경로·캐시 구분·실행 기록에 전달된다.
- 파일 경로와 SHA-256을 확인한 기본 제공 영상만 장면별 대조군 키를 받는다. 다른 장면의 무음본, 같은 이름의 업로드, 변경된 파일을 자동으로 짝짓지 않는다. 누락·변조·알 수 없는 선택은 명시적인 오류로 처리한다.
- 전체 CPU 검사 **400개 통과**. 실제 marimo 폼의 여섯 선택값 변환·제출, 업로드 검증, 원본/무음 구분, 다른 장면으로 바꿀 때의 캐시 분리, 같은 장면에만 대조군 연결, 미리보기와 계산 셀의 의존성 분리를 포함한다. 모델 입력 경계 검사는 실제 GPU 대신 테스트 대역을 사용했다.
- 실제 로컬 marimo 0.25.0에서 `CTP49906_REPLAY=1`로 실행했다. 셋업 셀을 교체하지 않았으며, 기존 설치 패키지와 로컬 프로젝트 경로를 사용했다. 장면 2 원본·장면 3 무음 미리보기가 해당 파일로 바뀌는 것, 두 폼에서 독립적으로 새 영상을 선택하는 것, 재생 모드의 추론 버튼 비활성 상태를 브라우저에서 확인했다.
- 두 한국어 노트북의 `marimo check --strict`, HTML/Studio 생성본 동기화, `git diff --check`를 확인했다. 내장 HTML판은 canonical 소스와 생성기를 통해 갱신했다.

이 기록은 드롭다운 연결과 CPU 경로 검증이다. 새 영상의 실제 Molab GPU 추론·직접 청취·새 저장 결과 묶음은 아직 검증하지 않았다. 이전 GPU 실측을 이번 영상과 버전의 실측으로 간주하지 않는다. 계획의 가이드 활동·질문 프리셋·18개 저장 결과는 이번 요청의 구현 범위에 포함되지 않는다.

## 실측 결과 — 2026-10-06

개인 Molab의 내장 HTML 폼에서 **입력 제출 → CUDA 계산 → 결과 갱신을 7회 확인했다.** GPU는 NVIDIA RTX PRO 6000 Blackwell Server Edition, 실행 device는 `cuda:0`, torch는 `2.11.0+cu130`이었다. 저장 예제 재생은 꺼져 있었다. 생성 파일의 SHA-256은 `763ee326fd0b9b0d84bc33fcf70d92c8e97f1de5d2a6d9ba2fa1167bcad25739`이며 원시 관측 파일의 소스 식별값과 일치한다.

별도 표기가 없는 실행은 기본 클립 `02321.mp4`, 8프레임을 사용했다. 다양성 metric은 레이어별 고유 예측 수 차이의 평균이며, 티처 포싱 metric과 단위가 다르다. 표의 값은 이번 입력·모델·실행 환경에서 관측한 결과다.

- 구간 입력의 초안 변경과 메뉴 이동에서는 forward 호출이 **32→32**, 기록이 1개로 유지되었다.
- 빈 프롬프트 제출은 거부되었고 **100→100**, 기록 4개로 유지되었다. 입력을 복구한 다음 제출에서는 **100→102**로 증가했다.
- 토큰 강조 임계값만 변경했을 때는 **102→102**, 기록 5개로 유지되었다.
- 실제 화면에서 발견한 숨겨진 중복 anchor와 shadow root 스타일 누락을 수정한 뒤 메뉴 이동과 카드 스타일을 확인했다.
- 1280×800과 820×900 창에서 세 입력 카드 모두 가로 넘침 없이 표시되었다. 좁은 창에서는 입력 grid가 한 열로 바뀌었다. 다섯 메뉴와 목차 복귀를 확인했고, 여섯 anchor ID는 DOM에 각각 한 번만 존재했다.
- 실행 중인 64개 셀을 배포 파일과 대조했다. marimo 공식 loader가 적용하는 들여쓰기 정규화를 반영한 AST가 **64개 모두 일치**했다.
- 자동 검사 **375개가 통과**했다. 이 중 HTML 실행판 검사는 24개이며 전체 notebook의 CPU replay 실행을 포함한다.
- Chrome에서 받은 `lab_evidence.json`과 `lab_log.md`의 7개 실행을 실제 관측과 대조했다. 두 파일의 전체 기록이 일치하며 **1,020개 대조 항목이 통과**했다. 티처 포싱 96개 토큰의 배열 길이·평균·합계와 `기준선 + Δ = 차단` 관계, 72개 다양성 레이어 행, 원본·무음 대조군의 설정 일치도 확인했다. 8→4프레임 변경 전후 오디오 토큰 수는 248개로 같았다.

메뉴 이동·내보내기·창 크기 변경을 마친 뒤에도 누적 forward 호출은 138회, 실행 기록은 7개로 유지되었다. 검증용 forward hook은 제거했고 결과는 보존했다.

원시 관측은 QA 작업폴더의 `outputs/molab-native-html-20261006/live-checks.json`, 내보내기 대조는 `export-checks.json`, 실행 셀 대조는 `runtime-parity.json`에 저장했다. 아래는 재검증에 사용할 구조 설명과 수행 기준이다.

검증한 7개 GPU 실행에서는 계산 오류가 없었다. Chrome console에는 Molab 호스트의 dialog 접근성 경고와 language-server 초기화 timeout이 있었으나 실험 계산과 결과 갱신은 완료되었다. 일부 캡션은 32토큰 상한에 도달했으며 화면에 잘림 가능성이 안내되었다. 다른 학생 계정의 동시 접속, 휴대전화 크기, 다크 모드는 이번 GPU 통합 검증 범위에 포함하지 않았다.

## 구현 경로

`CTP49906_avllm_molab_html_kr.py`는 기존 한국어 notebook에서 생성하는 Molab 내장 HTML 실행판이다. 원본 `CTP49906_avllm_molab_kr.py`와 `studio/ctp49906-kr/explore/`는 공식 Studio 실행 경로로 보존한다.

생성기는 설명과 화면 구성을 바꾸고, 실험 계산은 원본에서 가져온다. 세 실험의 HTML은 `mo.Html(...).batch(...).form(...)`으로 구성한다. HTML 안에는 기존 marimo 입력 요소가 들어가며, 제출된 값이 기존 결과 셀로 전달된다. 별도 서버·터널·브라우저용 RPC는 사용하지 않는다. 모델 로딩, GPU 함수, 입력 검증, 캐시, 기록 생성은 원본과 같아야 한다.

탐색 메뉴는 문서 안의 anchor 링크다. 탐색 대상 ID는 폼 바깥의 보이는 제목에 둔다. marimo가 batch 내부 template을 복제하므로 입력 template 안에 ID를 두면 숨겨진 복제본으로 이동할 수 있다. 메뉴 이동을 위해 입력 요소를 복제하거나 다시 마운트하지 않는다. 폼 입력 중에는 직전 실행 결과가 유지되고, 실행 버튼을 눌러야 새 설정으로 계산한다. 임계값은 이미 계산한 토큰 결과의 표시만 바꾼다.

입력 폼은 marimo의 shadow root 안에 렌더링된다. 카드의 테두리·여백과 입력 grid 스타일은 폼 HTML 안에 함께 둔다. 상위 목차 셀의 CSS만으로 폼이 꾸며졌다고 가정하지 않는다.

이 실행판을 공식 Studio 화면으로 표현하면 안 된다. 두 경로는 같은 분석 코드를 사용하지만 화면을 전달하는 방식이 다르다.

생성 결과와 원본 사이에서 실험 셀의 AST, 폼의 입력 요소·초기값·검증 함수·제출 설정을 비교한다. 각 batch 입력이 HTML에 한 번씩 배치되는지, Studio dependency/config 및 bundle 실행이 없는지 확인한다. 전체 notebook을 저장 예제로 실행하는 CPU replay 검사도 포함한다. 이 검사는 GPU를 요구하지 않으며, 실제 GPU 통합 검증을 대신하지 않는다.

## 개인 GPU 세션 준비

1. 자신의 Molab 계정에서 HTML 실행판을 Mirror from GitHub로 연다.
2. 개인 notebook의 GPU 설정을 켜고 실행한다. GPU 기종, CUDA 사용 가능 여부, 실제 모델 device와 사용 패키지 버전을 기록한다.
3. 원본 기본 샘플 `assets/02321.mp4`와 무음 대조군이 준비되었는지 확인한다. 샘플은 프로젝트에 포함되며 별도 업로드가 기본 절차는 아니다.
4. `USE_PRECOMPUTED=False`인지 확인한다. 초기 가이드 계산이 끝나고 오류가 없는 상태에서 입력 QA를 시작한다.
5. notebook 소스 SHA-256, helper 소스 revision, 모델 revision을 기록한다. 실제 실행 파일이 HTML 실행판인지 확인한다.

## 실제 브라우저 입력 → GPU → 결과 QA

공통 설정은 기본 클립, 8프레임, 기본 한국어 프롬프트, 캡션 상한 32토큰이다. 표의 작업은 브라우저의 HTML 폼에서 수행한다. Python 변수를 직접 바꾼 실행은 폼 제출 검증을 대신하지 못한다.

| 단계 | 브라우저 조작 | 합격 기준 |
| --- | --- | --- |
| 메뉴 이동 | 다섯 섹션 링크와 목차 복귀 링크 클릭 | 각 제목으로 실제 스크롤. 각 target ID는 DOM에 한 번만 있고 보이는 크기를 가짐. 입력 초안 유지 |
| 폼 배치 | 넓은 창과 좁은 창에서 세 입력 폼 확인 | 실제 shadow root 안의 카드 테두리·여백과 grid 적용. 입력·실행 버튼이 잘리거나 겹치지 않음 |
| 구간 A | 타깃 `video`, 레이어 `[0,12)` 제출 | GPU 생성 완료. 결과 설정, 캡션 비교, `band_sweep` 기록이 제출값과 일치 |
| 초안 변경 | 레이어만 `[12,24)`로 바꾸고 제출하지 않음 | 입력은 바뀌고 직전 결과는 `[0,12)` 유지. 계산 재실행 없음 |
| 구간 B | 변경된 구간 제출 | 새 GPU 생성. 결과·기록이 `[12,24)`로 갱신되고 `changed`에 `start`, `end` 표시 |
| 다양성 | `audio→video`, 전체 레이어, 기준선 비교 켬, 제출 | 기준선·녹아웃 GPU 순전파, 그래프·통계·`diversity` 기록 생성 |
| 티처 포싱 A | 타깃 `audio`, 레이어 `[0,12)` 제출 | GPU 채점 완료. 평균 Δ, 총 Δ, 전체 캡션, 토큰별 Δ와 기록 표시 |
| 잘못된 입력 | 티처 포싱 프롬프트를 공백으로 변경하고 제출 시도 | 한국어 검증 메시지. GPU 계산 없음. 직전 성공 결과 보존 |
| 복구·티처 포싱 B | 원래 프롬프트 복구, `[12,24)` 제출 | 새 GPU 채점과 설정·결과 갱신. 레이어 변경 시 같은 캡션 캐시 사용은 정상 |
| 표시 변경 | 강조 임계값 변경 | 토큰 강조와 집계만 변경. GPU 채점·run ID·원본 Δ 배열은 유지 |
| 기록 확인 | 실습 기록과 JSON/Markdown 확인 | 화면의 설정·metric·과학적 결과가 저장된 증거와 일치 |

가능하면 추가로 업로드 선택 후 파일 미선택, 빈 레이어 구간, 잘못된 고급 규칙을 확인한다. 검증 오류를 복구한 뒤 정상 제출이 가능해야 한다.

## 증거와 판정 시 주의점

- 설정 A와 B의 캡션이나 metric이 같을 수 있다. 결과가 같다는 이유만으로 재계산 실패로 판정하지 않는다. 새 설정이 적용된 계산과 결과 표시를 함께 확인한다.
- 원본 문자열의 ID 개수만 세어서는 브라우저 DOM의 숨겨진 복제본을 잡을 수 없다. 메뉴 이동은 실제 렌더링된 화면에서 확인한다.
- `run_id`는 설정과 결과의 content digest이며 같은 실행은 기록에서 합쳐진다. ID나 기록 행 수가 그대로라는 사실만으로 GPU 미실행을 증명할 수 없다.
- 초안·잘못된 입력·임계값 변경에서는 마지막 제출값과 결과, 계산 셀의 실행 상태를 함께 확인한다. QA 중 임시 forward hook을 쓰는 경우 계산을 바꾸지 않고 호출 수만 관측하며, 검증 후 제거한다.
- GPU 실행 증거에는 CUDA 모델 device, 계산 전후 호출 또는 실행 관측, 화면 결과, 저장된 설정과 metric을 함께 남긴다. CPU mock 테스트나 저장 예제 재생을 실제 GPU 실행으로 보고하지 않는다.
- 캡션 캐시나 인코딩 캐시 재사용은 정상이다. 티처 포싱의 구간 변경 뒤 채점 순전파까지 생략되면 실패다.
- 오류 메시지, 실행 종료, GPU 메모리 문제, 화면 잘림, 키보드 조작, 초안 유지 여부를 기록한다. 준비 완료는 확인한 범위로만 보고한다.

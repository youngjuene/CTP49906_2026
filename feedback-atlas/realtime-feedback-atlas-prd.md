# PRD: 실시간 프로젝트 피드백 지도 (Real-time Feedback Atlas)

**문서 상태**: Draft v0.1
**작성일**: 2026-09-07

> **가정**: 이 문서는 CTP49906 'Multimodal AI' 세션의 4주 워크숍(1~4주차, 4주차 학생 발표)에서
> 쓰인다고 가정하고 작성했습니다. 다른 과목/세팅이라면 2절 배경만 조정하면 나머지는 그대로 씁니다.

---

## 1. 배경

4주 워크숍은 학생이 modality pair를 골라 자신만의 atmospheric pipeline을 설계하고, 2주차에는
AVLLM/MLLM이 자신의 촬영 영상 속 주관적 감각 경험을 얼마나 서술하지 못하는지를 직접 실습하며,
4주차에 결과물을 발표한다. 이 발표·제작 과정에서 학생은 동료·청강생·강사로부터, 그리고 AI 모델의
해석적 코멘트로부터 피드백을 받는데, 지금은 이 피드백이 구두로 휘발되거나 채팅/메모에 흩어져
남아 나중에 다시 보기 어렵고, 무엇보다 "AI가 주는 의견"과 "사람이 주는 의견"이 실제로 얼마나
다른 지점을 짚는지 한눈에 비교할 방법이 없다.

## 2. 목표 / 비목표

**목표**
- 수업 중 실시간으로 들어오는 피드백을 발표 즉시 한 화면에서 볼 수 있게 한다.
- AI 의견과 인간 의견을 같은 의미 공간에 놓아, 두 집단이 실제로 같은 지점을 이야기하는지
  다른 지점을 이야기하는지를 위치·군집으로 드러낸다 — 이는 이 세션이 다루는 "모델이 주관적
  경험을 어디까지 서술하는가"라는 질문과 직접 맞닿는다.
- 주차별로 쌓인 피드백을 나중에 다시 걸러보며 학생 프로젝트가 어떻게 변해왔는지 돌아볼 수
  있게 한다.
- 참여 장벽을 낮춘다: 링크 하나로 접속, 비밀번호 없이 ID 확인만으로 즉시 입력.

**비목표 (이번 버전에서 다루지 않음)**
- 참가자용 정식 로그인/회원가입 — 비밀번호나 가입 절차는 두지 않는다. 다만 5.1절처럼
  ID가 사전 등록된 명단에 있는지 정도는 확인한다. 관리자 화면 접근에는 별도의 경량
  인증을 둔다(5.6절).
- 클래스 규모를 넘어서는(수천 명 단위) 트래픽 처리
- 피드백에 대한 자동 요약·평점·채점 연동
- 모바일 전용 UI 최적화 (반응형 정도만 고려, 네이티브 앱 아님)

## 3. 사용자

| 유형 | 설명 | 앱에서 하는 일 |
|---|---|---|
| 수강생 | 자기 프로젝트를 발표하고, 동료 프로젝트에도 피드백을 남김 | 피드백 입력, 지도 열람 |
| 청강생 | 정식 수강 없이 참관, 피드백만 남김 | 피드백 입력, 지도 열람 |
| 강사/조교 | 수업 진행, 필요시 피드백 입력, 지도로 전체 흐름 관찰 | 피드백 입력(선택), 지도 열람, 대상 학생 명단·참가자(작성자) 명단 사전 설정 |
| 관리자(강사/조교 겸임) | 작성자 실명을 알아야 하는 운영 주체 | 관리자 모드 접근, 작성자 기준 조회(5.6절) |

## 4. 핵심 사용 시나리오

1. **발표 중 실시간 입력**: 학생이 프로젝트를 발표하는 동안, 참석자들이 각자 기기에서 공유된
   링크로 접속해 의견을 입력한다. 입력 즉시 지도에 새 점이 뜨고, 다른 모든 참석자 화면에도
   동시에 반영된다.
2. **주차 필터로 되짚기**: 발표가 끝난 뒤 학생이 1~4주차 체크박스를 껐다 켜며, 자기 프로젝트에
   대한 의견이 주차가 지나며 어떻게 바뀌었는지(혹은 반복되는지) 확인한다.
3. **AI 의견 대량 반영**: 강사가 특정 발표 영상/텍스트에 대해 AI 모델이 생성한 해석 코멘트
   여러 건을 (수동 입력 또는 준비된 스크립트로) 올리면, 기본 태그가 AI이므로 별도 표시 없이도
   인간 의견과 구분되어 지도에 쌓인다.

## 5. 기능 요구사항

### 5.1 랜딩 페이지 (ID 확인)
- 공유 링크로 접속하면 가장 먼저 랜딩 페이지가 뜬다. 입력 항목은 "내 ID" 하나뿐.
- 입력한 ID를 사전 등록된 참가자 명단(수강생+청강생, 7절 참고)과 대조한다.
  - **명단에 있으면**: 메인 화면(피드백 입력 + 지도)으로 진입. 같은 세션에서는 다시
    입력할 필요 없이 유지된다.
  - **명단에 없으면**: 오류 메시지를 보여주고 재입력을 유도한다(오탈자 가능성 우선 안내).
    반복 실패 시 강사/조교에게 등록을 요청하도록 안내한다.
- 대조는 완전 일치가 아니라 공백 트림·대소문자 무시 정도의 완화된 매칭을 적용해, 사소한
  오타로 반복 실패하는 일을 줄인다.
- 대상 학생(target_id) 선택은 랜딩 페이지가 아니라 메인 화면의 피드백 입력 폼에서 이뤄진다
  (기존과 동일).

### 5.2 피드백 입력
- 입력 항목: 내 ID(작성자), 대상 학생, 의견 텍스트, 구분(AI/인간), 주차(1~4).
- 제출 시 검증: 의견 텍스트 비어있으면 제출 불가. 그 외 항목은 비어 있어도 기본값으로 채움.
- 구분(AI/인간)은 역할과 무관하게 누구나 선택할 수 있다 — AI 의견도 강사·조교만이 아니라
  수강생·청강생 누구든 작성·추가할 수 있다. 다만 이는 자기 신고 방식이라 오분류 가능성은
  11절에서 별도로 다룬다.

### 5.3 태그 체계
- **구분(source)**: `ai` | `human`, **기본값 `ai`**. 사용자가 별도로 바꾸지 않는 한 AI로 기록된다.
- **주차(week)**: `1`~`4` 중 하나. 자유 날짜/시간이 아니라 이 네 값만 존재.
- 두 태그 모두 검색·정렬용이 아니라 시각화 필터/구분 기준으로만 쓰인다.

### 5.4 실시간 시각화 (일반 참가자 화면)
- 의견 하나 = 지도 위 점 하나. 위치는 의견 텍스트의 의미 유사도로 결정(비슷한 내용일수록
  가까이 위치).
- 색상 = 대상 학생, 모양 = 구분(AI/인간)으로 인코딩해, 동일 화면에서 "누구에 대한 의견인지"와
  "누가/무엇이 말한 의견인지"를 동시에 읽을 수 있게 한다.
- 점에 마우스를 올리면 원문, 대상 학생, 주차가 보인다. **작성자(reviewer_id)는 일반 화면
  어디에도 노출하지 않는다** — 서버에는 저장되지만 이 화면으로는 전달하지 않는다.
- 새 의견이 들어오면 모든 접속자 화면에 지연 없이(수 초 이내) 반영된다.

### 5.5 필터링
- 화면 상단에 1~4주차 체크박스. 체크 해제한 주차의 점은 화면에서 숨겨지되, 좌표는 그대로
  유지되어 주차를 넘나들며 켜고 꺼도 지도가 흔들리지 않는다.
- 구분(AI/인간)은 필터가 아니라 항상 모양으로 함께 표시(둘 다 상시 노출).

### 5.6 관리자 모드 (신규)
- 강사/조교(관리자)만 접근하는 별도 화면 또는 모드 토글. 최소한의 경량 인증(예: 고정 접근
  코드)으로 구분하며, 일반 참가자 플로우에는 로그인 절차를 추가하지 않는다.
- 관리자 모드에서는 각 점에 작성자(reviewer_id)가 표시되고, 특정 작성자를 선택·검색하면
  그 사람이 남긴 의견만 강조되거나 목록으로 걸러진다.
- 관리자 모드도 5.4절과 동일한 지도·데이터를 보되 노출 범위만 다르다 — 별도의 데이터셋을
  두지 않는다.

## 6. 비기능 요구사항

- **로컬 처리**: 의견 텍스트의 임베딩 계산은 외부 LLM API 호출 없이 로컬 모델로 수행한다
  (비용·응답속도·수업 중 네트워크 의존성을 이유로).
- **한국어 지원**: 의견은 대부분 한국어로 작성되므로, 임베딩 모델은 한국어 의미 유사도를
  충분히 잡아야 한다.
- **동시 접속 규모**: 한 세션 기준 최대 수십 명, 누적 의견 수는 학기 전체로도 수백~千 건 이하로
  가정한다.
- **응답성**: 제출부터 모든 화면 반영까지 체감상 즉시(수 초 이내)여야 한다 — 발표 도중 쓰는
  도구이므로 지연이 크면 참여도가 떨어진다.
- **데이터 보존**: 세션/서버가 재시작되어도 그동안의 의견이 유지되어야 한다.
- **개인정보 분리**: 작성자 실명(또는 실명급 식별자)은 서버에 저장되지만 일반 참가자 화면에는
  전달하지 않는다. 실명 조회·검색은 관리자 모드로만 가능하다(5.6절).
- **학기 후 비식별화**: 학기가 끝나면 `reviewer_id`(및 필요시 `target_id`)를 개인 식별이
  불가능한 코드로 치환해 보관하고, 실명-코드 매핑은 별도로 파기하거나 격리 보관한다. 치환
  이후에는 관리자 모드의 "작성자로 조회" 기능도 더 이상 실명 기준으로 동작하지 않는다.

## 7. 데이터 모델

| 필드 | 타입 | 설명 |
|---|---|---|
| id | string | 의견 고유 식별자 |
| reviewer_id | string | 작성자(수강생/청강생) ID, 자유 입력. 일반 참가자 응답에서는 제외되고 관리자 API/화면에만 포함 |
| target_id | string | 피드백 대상 학생(프로젝트), 사전 등록 목록 중 선택 |
| text | string | 의견 원문 |
| source | enum(ai, human) | 기본값 ai |
| week | enum(1,2,3,4) | 주차 |
| timestamp | datetime | 제출 시각 |
| x, y | float | 의미 유사도 기반 2D 좌표(파생 값, 매 제출마다 전체 재계산) |

> 학기 종료 후에는 `reviewer_id`(및 필요 시 `target_id`)를 비식별 코드로 치환한 별도
> 아카이브를 만든다 — 원본 레코드를 직접 덮어쓰지 않아, 실수로 되돌릴 수 없는 치환이
> 일어나지 않게 한다.

**참가자 명단 (사전 등록, 랜딩 페이지 대조용)**

| 필드 | 타입 | 설명 |
|---|---|---|
| id | string | 랜딩 페이지 대조 기준 값(= `reviewer_id`로 그대로 쓰임) |
| display_name | string | 실명 또는 실명급 식별자 — 관리자 모드에서만 노출 |
| role | enum(student, observer) | 수강생/청강생 구분 |

강사/조교가 수업 전 이 명단을 등록해두며, 명단에 없는 ID는 랜딩 페이지를 통과하지 못한다.

## 8. 시스템 개요 (참고용 — 상세 구현은 별도)

- **임베딩**: 로컬 오픈 가중치 모델(예: EmbeddingGemma)로 의견 텍스트를 벡터화. 한국어
  품질이 부족하면 한국어 특화/다국어 모델로 교체 가능해야 함.
- **2D 투영**: 의견이 적을 때(콜드스타트)는 PCA, 충분히 쌓이면 UMAP으로 전환.
- **실시간 전달**: 서버가 접속자 전원에게 갱신된 전체 데이터를 푸시(폴링이 아닌 push 방식).
- **접속 경로**: 하나의 서버가 지도를 서빙하고, URL을 공유 — 강의실 내부망 또는 임시 공개
  터널을 통해 외부 접속도 가능해야 함.
- **관리자 인증**: 별도 계정 시스템 없이, 고정 접근 코드 등 경량 방식으로만 구분.

## 9. 성공 지표

- 발표 세션당 최소 N건 이상의 실시간 의견 입력(최초 목표치는 강사가 시범 운영 후 정함).
- 발표 종료 후 "AI 의견 군집과 인간 의견 군집이 실제로 갈라지는 사례"를 최소 1건 이상
  수업에서 언급/토론할 수 있는가 — 이 도구가 단순 취합함을 넘어 논의를 촉발했는지의 정성 지표.
- 참석자가 별도 안내 없이 1분 내로 첫 의견을 제출할 수 있는가(온보딩 마찰 지표).

## 10. 범위 외 / 향후 과제

- 의견에 대한 답글/스레드 기능
- 학생별 요약 리포트 자동 생성(예: "이번 주 내 프로젝트에 대한 의견 요약")
- 다중 세션(여러 과목/학기) 데이터 분리 및 아카이빙

## 11. 리스크 및 오픈 이슈

- ~~익명성~~ → **해결**: 그래프 노드에는 작성자를 노출하지 않고, 관리자 모드에서만 실명
  기준 조회가 가능하도록 결정됨(5.4, 5.6절). 남은 질문: 누구에게 관리자 권한을 줄지, 접근
  코드가 새어나갔을 때 어떻게 갱신할지.
- ~~AI 의견의 출처~~ → **부분 해결**: 역할 제한 없이 누구나 AI 의견을 작성·추가할 수 있도록
  결정됨. 다만 태그가 자기 신고 방식이라 인간이 쓴 의견을 AI로(또는 그 반대로) 잘못 표시할
  가능성은 남아 있어, 성공 지표 2번(AI-인간 군집 비교)의 신뢰도에 영향을 줄 수 있다.
- ~~데이터 처리 방침~~ → **해결**: 학기 종료 후 개인식별 불가능한 코드로 치환해 보관하기로
  결정됨(6, 7절). 다만 치환 시점(예: 성적 확정 직후 일괄 처리)과 원본 매핑 파기 방식은 아직
  세부 절차로 남아 있다. 이 데이터를 교육 연구 목적으로 쓰는 경우, 수업 참여와 별도로 동의를
  받고 성적 확정 후에만 분석하는 절차가 필요할 수 있다(과목 운영 방침에 따름).
- **네트워크 의존**: 강의실 와이파이가 불안정하면 실시간성이 흔들린다. 오프라인 큐잉/재전송
  등 완화책이 필요한지 검토.
- **관리자 접근 통제**: 고정 접근 코드 방식이 실제로 충분한 보안 수준인지, 여러 명이 관리자
  역할을 겸할 때 코드를 어떻게 나눠 관리할지 정해야 한다.
- **명단 밖 참가자**: 수업 중 갑자기 참여하는 청강생처럼 명단에 없는 사람은 랜딩 페이지를
  통과하지 못한다. 관리자가 수업 중 실시간으로 명단에 추가할 수 있어야 하는지, 아니면
  사전 등록을 엄격히 요구할지 정책이 필요하다.

## 12. 용어

- **의견(opinion/feedback)**: 한 참석자가 한 학생의 프로젝트에 대해 남긴 한 건의 텍스트.
- **구분(source)**: 의견이 AI가 생성한 것인지 사람이 작성한 것인지의 태그.
- **지도(map)**: 의견들을 의미 유사도 기준 2D 좌표에 뿌린 실시간 시각화 화면.
